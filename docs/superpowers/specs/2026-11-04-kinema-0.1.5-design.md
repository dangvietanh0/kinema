# Kinema Studio 0.1.5 — workspace shell, rig editing, graph editor, shading and export

Date: 2026-11-04
Base: `feat/professional-rebuild` @ `faad432`
Extends: `2026-11-03-kinema-wave-3-design.md` (binding touch rules, renderer
gate, rig subset, timeline budget, material model and the no-new-shader
ruling).
Supersedes, for the points below only: the three-arrangement top bar, the
permanent tool rail, the viewport header, the right panel rail, the bottom
action bar, the status bar on touch, the docked scene column, the
timeline-as-overlay model, the rig toolbar's edit-mode lockout, and the
speed-graph-as-a-compact-sheet model.

## 1. Intent

0.1.0 works, but its workbench is crowded and several core paths are harder
than they should be. 0.1.5 is a focused usability release:

1. **Replace the crowded shell with a mode-based workspace.** The user picks
   **Scene / Shading / Rig / Animate / Render** from one workspace chip. Only
   the current workspace's actions are visible. Shading, rigging and rendering
   stop occupying permanent chrome.
2. **Make the stage the first surface.** A 44 dp top bar, one 44 dp contextual
   action row and a 44 dp transport are the only permanent chrome. Panels open
   on demand; the scene column and the right icon rail are gone.
3. **Fix rig editing.** Any bone can be selected and dragged in one gesture,
   Pose and Edit both expose Rotate/Move, a visible 3-axis gizmo edits the
   active bone, and the idle overlay stops redrawing every frame. The
   timeline never covers the rig again.
4. **Simplify graph editing.** The graph becomes a segment editor with
   **Ease / Value / Speed**, large handles, a preset rail and real segment
   selection. Custom cubic easing is baked into real animation keys so
   playback and export remain honest.
5. **Add the missing "in camera" path.** The viewport offers the real
   document-camera look-through, with camera selection, switching and exit.
6. **Polish shading and export.** Shading gets a real material workspace;
   Render gets a real GLB scene export alongside the existing still, PNG
   sequence, GIF, MP4 and camera-track paths.
7. **Remove semantic icon duplicates and ship 0.1.5.** Every visible action
   gets one meaning and one glyph, and the version is bumped everywhere
   user-visible and in CI.

The references are used as **feature models only**:
`unnamed.png` (Alight Motion: segment graph, Ease/Value/Speed, large handles,
presets), `unnamed.webp` (Prisma 3D: one compact interface bar, stage first)
and `unnamed (1).webp` (Reconn4D: workspace controls separated from the
stage). Their colours, radii and branding are not copied.

## 2. Rulings

These rulings are binding for 0.1.5.

- **R1 — Five workspaces, not tabs.** `Scene`, `Shading`, `Rig`, `Animate` and
  `Render` are mutually exclusive editing modes. There is no permanent tab
  strip; the workspace chip is the only permanent mode affordance.
- **R2 — No permanent shading, rig or render chrome.** Material controls,
  rig controls and export controls exist only inside their workspace (and in
  the inspector/settings sheets where they already belong as data entry).
- **R3 — Stage first.** The stage owns the centre at every supported size.
  Side panels are reserved only inside Shading/Rig/Render at ≥ 768 dp wide;
  everywhere else they are overlays.
- **R4 — "In camera" means real look-through.** It enters the existing
  document-camera view (`EditorView.enter_look_through`), switches between
  scene cameras and exits via the camera control, the view's X or Android
  Back. There is no simulated viewfinder frame.
- **R5 — Rig edit parity.** Pose and Edit both allow Rotate and Move. Edit
  rotates/translates the rest bone; Pose rotates/translates the pose bone.
  Imported skeletons keep rest editing locked and pose editing live.
- **R6 — Segment graph model.** The graph edits one selected segment at a
  time, with direct segment selection from the dope sheet or the graph and a
  preset rail. It does not zoom the whole track by default.
- **R7 — Custom cubic is real data.** Two-handle cubic easing is sampled into
  real `Animation` keys (1–48 interior keys on the document frame grid,
  endpoints preserved) and the authored handles are stored as segment
  metadata in project format 4. If the bake cannot pass its tests, the
  fallback is the engine's one-scalar transition with one handle; the
  fallback is not shipped silently and requires a spec amendment.
- **R8 — No fake speed editing.** The Speed tab is a real velocity readout of
  the same sampled channel. It is read-only and says so; editing happens in
  Ease (timing) and Value (value). A decorative draggable speed curve is
  forbidden.
- **R9 — Shading stays on real materials.** Shading reuses
  `MaterialSystem` and `StandardMaterial3D`/`ORMMaterial3D`. Wave 3's
  **no new custom shaders** ruling remains in force.
- **R10 — GLB export is real.** It writes a real `.glb` with
  `GLTFDocument`, includes the active clip's animation, excludes hidden
  objects and editor-only marker nodes from the copy, and is verified by
  re-importing the produced file. No share sheet is faked.
- **R11 — One glyph, one meaning.** A glyph keeps one meaning across the
  shell; repeated `add` actions share `plus` because they share the add
  meaning. Within one visible top/context/transport state, two different
  action ids may not use the same icon. The icon contract in §5.10 is
  enforced by a test.
- **R12 — Tests move with the shell.** `layout.gd`, `smoke.gd`,
  `timeline_workspace.gd`, `rig.gd`, `object_visuals.gd` and `capture.gd`
  are migrated or rewritten against the workspace shell. Old assertions are
  migrated or replaced with equal-or-stronger assertions; they are not
  deleted to make the build green.
- **R13 — Version 0.1.5, versionCode 2.** The app, Android manifest, CI
  version flags, artifact names, README and BUILD.md agree.
- **R14 — "Layout" and "workspace" are different words.** Layout means
  `compact | studio | desktop`. Workspace means
  `scene | shading | rig | animate | render`. The existing layout API is
  renamed in W1 so the two can never be confused again.
- **R15 — Honest device status.** Nothing in this spec claims physical-device
  validation. The APK is produced by GitHub Actions and verified by
  inspection; device checks remain listed in §13.

## 3. Global constraints

- **Platform:** Android 15–17 target, touch first, landscape priority.
  Desktop layouts remain a first-class window mode but are not the product's
  primary target.
- **Touch targets:** 44 dp minimum in Compact and Studio; 44 dp rows in
  menus and panels. Primary actions are 96 × 44 dp. Desktop may use 28–32 dp
  mouse controls; the 44 dp floor applies to the touch layouts only.
- **Landscape budgets:** the shell must fit 800 × 360, 915 × 412, 600 × 960,
  360 × 640, and desktop 1024 × 768 through 2560 × 1600 without horizontal
  overflow.
- **Chrome:** pure black window and stage; achromatic graphite elevation;
  red only for destructive/error. No new colour accents.
- **Type:** IBM Plex Sans and IBM Plex Mono, existing tokens. 11 sp is the
  product floor; 10 sp only on ruler ticks and non-essential mono badges.
- **Corners:** square panels. Existing 2 px control and 4 px floating-surface
  radii stay; no new large radii.
- **No fake features:** every enabled control performs the action its label
  claims. A capability the platform cannot provide is disabled with the real
  reason.
- **No new shaders:** no `.gdshader` file is added or modified in 0.1.5.
- **Build:** only GitHub Actions `assembleStandardDebug`, arm64-v8a, CI debug
  keystore, package `studio.kinema.app`.
- **Data compatibility:** 0.1.0/0.1.1 project files (format 3 and older) load
  unchanged. Format 4 adds optional segment metadata.

## 5. W1 — Workspace shell, camera view, icons, version

### 5.1 Terms and API rename

- `layout` / `layout_mode`: `compact`, `studio`, `desktop`, resolved from
  Auto as today.
- `workspace`: `scene`, `shading`, `rig`, `animate`, `render`.
- Renames in W1:
  - `Editor.set_workspace_mode(mode)` → `Editor.set_layout_mode(mode)`.
  - `signal workspace_mode_changed` → `signal layout_mode_changed`.
  - property `workbench_mode` → `layout_mode`; update Main and tests.
  - `workspace_sheet.gd` → `interface_sheet.gd`; title **Interface**.
  - `_workspace_sheet` → `_interface_sheet`.
  - `open_timeline_workspace` / `close_timeline_workspace` are removed in W1;
    W1 mounts the existing `Timeline` component in the Animate pane; W3
    extends that pane with the new graph editor.
- New API:
  - `Editor.workspace() -> String`
  - `Editor.set_workspace(id: String, persist := true) -> void`
  - `signal workspace_changed(id: String)`
  - `Editor.workspace_menu_open() -> bool`
- Persistence: `Prefs.editor.workspace` (string). On project open, restore the
  saved workspace if it is valid; otherwise `scene`. A Rig workspace with no
  rig stays on Rig and shows its empty state; it does not silently jump.
- W3 owns `Prefs.editor.animate_stage` (bool, remembers the Animate stage
  preview) and `Prefs.editor.graph_tab` (string, `ease|value|speed`). W1 does
  not read or write them.

Touch (Compact and Studio):

├──────────────────────────────────────────────────────────┤
│ context row                                      44 dp   │  actions for the current workspace
├──────────────────────────────────────────────────────────┤

Desktop:

- `GUTTER` stays 1 dp between shell bands; bands are separated by elevation,

- The status bar is no longer permanent. Its content moves to the existing

  the optional strip is enabled.
- The safe area is applied once by `Main`; the editor does not add its own
  insets.

### 5.3 Top bar

One `WorkspaceBar` component replaces `top_bar.gd` for all layouts.

- Height: 44 dp touch, 32 dp desktop.
- Left: Back (44/28), workspace chip (min 96, max 144; text + `chevron-down`).
- Right: Undo (`undo-2`), Redo (`redo-2`), Save (`save`), Menu (`menu`).
- No project title in the bar. The chip tooltip and the workspace menu header
  show the project title.
- The chip has no workspace icon; it shows the workspace name only. This
  keeps "only the current workspace name permanently visible" true and
  avoids duplicating glyphs used by context actions.
- Save stays enabled even when the document is clean and answers with a
  toast when there is nothing to save; a disabled save makes users think
  saving is broken. A small dot on the chip marks unsaved state.
- The menu (not the workspace menu) contains, in order:
  - Project settings (`settings`)
  - Import 3D model (`upload`)
  - Graphics and performance (`gauge`)
  - Interface and scale (`monitor`)
  - Performance overlay (`timer`)
  - Instrumentation strip (`rows-3`, desktop only; hidden in touch layouts)
  - Separator
  - Gesture guide and shortcuts (`keyboard`)
  - About Kinema (`info`)
  - Separator
  - Close project (`x`)
  All rows are 44 dp touch / 32 dp desktop.

### 5.6 Stage and panel host

- `StageHost` owns the viewport and the workspace surfaces. The stage is a
  real child of the layout, never covered by the timeline in Scene/Shading/
  Rig/Render.
- `WorkspacePanel` is one reusable panel host:
  - Modes: `hidden`, `reserved`, `overlay`.
  - Reserved width: `clamp(width * 0.34, 280, 360)`; only in Shading, Rig and
    Render at ≥ 768 dp. At the threshold the panel is 280 dp and the stage
    keeps 487 dp (768 − 280 − 1 dp gutter); it never drops below 480 dp.
  - Overlay width: `min(width - 16, 400)`; scrim; 44 dp close row; Android
    Back closes it before changing workspace.
  - Header 44 dp: title (13 sp), optional state badge, close button on
    overlay only.
  - Content is a reparented existing panel; the host never rebuilds document
    state.
- Scene workspace: no reserved panel. `scene_tree` and `inspector` toggle
  overlay panels. Opening one closes the other; tapping the same action closes
  it. The panel starts at the top bar's bottom edge, not over it.
- Shading: panel is the material workspace (§8). Rig: panel is the existing
  rig panel (§6.6). Render: panel is the render/export surface (§8.3).
- Animate: no side panel; the timeline pane fills the body below an optional
  stage preview.
- The old `_scene_column`, `_scene_rail`, `_panel_rail`, `_dock` stacked
  pages and the drawer scrim are removed. One panel host replaces them.
- The outliner and inspector keep their existing content and signals; only
  their mount point changes. Search/selection state survives reparenting.

### 5.7 Transport

A 44 dp `TransportBar` (32 dp desktop) sits at the bottom of Scene, Shading,
Rig and Render.

- Play/Pause (`play`/`pause`, 44) — real document playback.
- Skip to start (`skip-back`, 44).
- Timecode label, mono 12, flexible; tapping it opens the frame/time entry
  sheet (existing behavior).
- Add key at playhead (`diamond-plus`, 44) — keys the selected object's
  transform (position, rotation and scale) through
  `Document.insert_transform_keys()`, the existing real key path.
- Animate (text only, 96) — switches to the Animate workspace at the
  playhead.
- No loop/snap/delete here; they belong to Animate.
- While no object is selected, Add key is disabled with "Select an object to
  add a key."
- In Animate, this bar is replaced by the timeline pane's own transport
  (§7.1).

### 5.8 Timeline visibility rules

- Scene/Shading/Rig/Render: **no timeline panel and no dope sheet overlay**.
  The transport is the only time control.
- Animate: the timeline pane is part of the layout, below the stage.
- The old bottom-anchored `_timeline_panel` and its `SHORT`/`FOLDED` overlay
  behavior are deleted. `Timeline` remains the dope-sheet/content component;
  it is mounted in the Animate pane, not over the stage.
- Entering Rig closes any open Animate pane and reparents the timeline only
  when Animate is selected. No timeline node is a child of the stage host.

### 5.9 In camera

Entry points:
- Scene context `camera_view`.
- Render context `camera_view`.
- The inspector's existing "Look through" primary action (routed through the
  editor, not directly to the view).

Menu:
- Title `CAMERA`.
- One 44 dp row per scene camera, sorted by name, `camera` icon, current one
  checked. Tapping enters or switches. A hidden camera is shown disabled with
  the reason "Camera is hidden." instead of failing silently.
- Separator.
- `Add camera…` (`plus`), 44 dp — opens the Add sheet with the Camera item
  visible. Disabled while in camera view with reason "Exit camera view to add
  a camera."
- `Exit camera view` (`x`), 44 dp — only while active.

Behavior:
- `Editor._enter_camera_view(id)` is the only entry point. If look-through is
  active, it calls `EditorView.switch_look_through_camera(id)`; otherwise it
  calls `EditorView.enter_look_through(id)`. On success it records
  `_look_camera_id` and updates the chip.
- `EditorView.switch_look_through_camera(id) -> bool` validates the camera
  object and visibility, updates `_look_camera_id`, copies the camera
  transform and FOV, and leaves `_look_saved`, the grid, the HUD and the
  editor chrome untouched. It does not emit `look_through_exited`. It returns
  false and changes nothing for a missing, non-camera or hidden target.
- `EditorView.enter_look_through(id)` delegates to
  `switch_look_through_camera(id)` when look-through is already active, so
  there is one camera-switch implementation and no exit/re-entry cycle.
- While active:
  - The top bar remains 44 dp: Back, `Camera: <name>` chip (no icon),
    and an Exit X (`x`, 44). Undo, Redo, Save and Menu are hidden because
    camera viewing is not an edit.
  - Context row and transport are hidden; the stage takes their height.
  - The view's own exit control remains visible and routes through the same
    exit path.
  - Rig overlay, video reference, perf overlay, grid and editing chrome stay
    hidden, exactly as the existing look-through path already enforces.
- Switching cameras uses `EditorView.switch_look_through_camera(new_id)`
  while active. It does not leave look-through, does not emit
  `look_through_exited`, and does not re-save `_look_saved`; the editor
  updates `_look_camera_id` and the chip. No document state changes.
- Exit paths: top-bar X, view X, Android Back, or selecting "Exit camera
  view". Exit restores the previous layout exactly.
- The editor watches `Document.scene_changed`: if `_look_camera_id` no longer
  resolves to a visible camera object, it exits look-through and shows the
  toast "Camera removed — returned to the editor view."
- If no scene camera exists, `camera_view` stays enabled but opens the menu
  with the empty message "No scene cameras. Add one to look through it." and
  the Add camera row. The control never pretends there is a camera.

### 5.10 Icon contract

One icon, one meaning. The following assignments replace the current
semantic duplicates:

| Meaning | Icon | Replaces |
|---------|------|----------|
| Camera object / in-camera / camera menu | `camera` | `camera` used for render sheet and quick still |
| Render workspace primary | `clapperboard` | `camera` |
| Render preview | `eye` | `play` (which means playback) |
| Still image export | `image` | `camera` |
| PNG sequence | `film` | `film` used for video reference |
| Video reference | `video` | `film` |
| Save still to disk | `download` | `download` reused for generic save |
| Save project | `save` | — |
| Frame selection | `focus` | `focus` and `maximize` mixed |
| Add camera / add object / add material / add bone | `plus` | — |
| Add keyframe | `diamond-plus` | — |
| Duplicate | `copy` | — |
| Delete | `trash-2` | — |
| Reset pose / reset transform | `rotate-ccw` | `restart` (reserved for renderer restart only) |
| Restart render preview | `restart` | — |
| Scene tree | `layers` | — |
| Inspector / properties | `sliders-horizontal` | — |
| Side panel toggle | `panel-right` | — |
| View preset | `orbit` | — |
| Grid | `grid-3x3` | — |
| Directional light | `sun` | — |
| Omni light | `circle-dot` | — |
| Add light | `lightbulb` | — |
| Context overflow | `ellipsis-vertical` | `ellipsis-vertical` on the top bar |
| Project menu | `menu` | `ellipsis-vertical` |

Rules:
- `camera` never means render.
- `restart` never means reset.
- `play` never means preview.
- `focus` never means fullscreen.
- An icon-only button always has an accessible name and a tooltip. If a
  meaning is not in this table, it gets a new semantic mapping before it ships.
- The icon contract test walks the visible top bar, context bar and transport
  in each workspace and asserts that no two different `action_id`s share an
  `action_icon`. It also asserts every icon file exists.

### 5.11 Desktop mini bar

- Top 32 dp, context 36 dp, transport 32 dp, optional instrumentation 20 dp
  (off by default; toggled by the desktop-only project-menu row).
- Mouse controls: 28 px icon buttons, 32 px time fields, 11 sp labels; no
  forced 44 dp hit in desktop.
- The same workspace chip and five-row workspace menu.
- Hover states use the existing `SURFACE_HOVER`; keyboard focus uses the
  existing focus ring.

### 7.2 Segment model

- A **segment** is one editable interval on the selected channel. There are
  two kinds:
  - a **recorded segment**: a `curve_segments` record's authored `[start,end]`
    span, containing any number of baked keys;
  - a **plain segment**: the interval between two consecutive keys not
    covered by a record.
- In Graph a recorded segment is one selectable unit; its interior baked keys
  are not separate segments. In Dope, tapping any key or band inside a
  recorded span selects the record.
- Selection identity is `object + channel + start + end` plus the kind
  (`record` or `plain`). It is re-resolved against the document on every
  selection change and every redraw; if the exact span no longer exists,
  selection falls back to the plain interval containing the playhead, then
  clears. Interior baked keys never become the selected interval.
- Segment selection sources:
  - tap a segment band in the dope sheet;
  - tap between two keys, or on an interior baked key, in the graph plot;
  - previous/next segment buttons in the pane header. They walk the merged
    list of recorded spans and plain key intervals; a record counts once and
    its interior keys are skipped.
- The selected segment is highlighted in both the dope sheet and the graph.
  The graph zooms to the recorded span or plain interval with 24 dp
  horizontal padding, or to the whole track when no segment is selected.
- The graph header shows `Object · channel · component · start → end` and the
  key count. It never claims a custom curve when the data is a plain
  transition.
- Segment selection is not a document change and is not undoable.

### 7.4 Ease tab

The Ease tab edits the selected segment's timing:

- When the segment has no custom metadata and its engine transition is within
  0.001 of 1.0, the handles start at (1/3, 1/3) and (2/3, 2/3).
- Legacy engine ease: a segment with no metadata and a transition outside
  1.0 ± 0.001 shows a `Engine ease` badge and one 44 dp exponent field (0–4,
  the value returned by `track_get_key_transition`) instead of cubic handles;
  a one-scalar engine ease is not a cubic and the UI must not pretend it is.
  A 96 × 44 `Bake ease` action samples that engine ease into real keys with
  the same frame-grid and transition-1.0 rules and records
  `family: "baked"`, preset `engine`, with no handles. A `Convert to cubic`
  action (96 × 44) replaces the baked preset with linear cubic handles at the
  current endpoint values; the first handle drag then bakes the new curve.
  Conversion is one undo entry. The exponent field itself is one undo entry
  per release.
- Two cubic handles:
  - `out` handle controls the departure (x1, y1);
  - `in` handle controls the arrival (x2, y2);
  - x is clamped to [0, 1]; y is clamped to [−2, 3] so overshoot is real but
    bounded.
- Dragging a handle previews the analytic curve in the plot. On release, the
  segment is re-baked once (one undo entry) and the playhead seeks to the
  current frame.
- The curve math is `SpeedCurve.cubic_ease(t, x1, y1, x2, y2)`: the cubic
  Bézier through (0,0), (x1,y1), (x2,y2), (1,1). `x1` and `x2` are clamped to
  [0,1] so x(s) is monotonic; solve x(s) = t with Newton and fall back to
  bisection, then evaluate y(s). `f(0)=0`, `f(1)=1`.
- Baking inserts keys strictly inside the segment on the document's frame
  grid. Let `start_frame = round(start * fps)`, `end_frame = round(end * fps)`
  and `span_frames = end_frame - start_frame`. If `span_frames < 3` the
  segment cannot carry a real interior sample, so handle dragging is disabled
  with "Segment too short to bake (3 frames minimum)" and no metadata is
  written. Otherwise `n = clampi(span_frames - 1, 1, 48)`; for `i` in `1..n`
  the sample frame is `start_frame + round(i * span_frames / (n + 1))`.
  Duplicate frames are collapsed. Sample times are `frame / fps` and always
  fall strictly inside `(start, end)`. Endpoint keys and values are preserved
  and no inserted key lands on an endpoint. A 1 s segment at 30 fps bakes 29
  interior keys; a 10 s segment bakes 48.
- Every baked key from the segment start through the last interior sample is
  set to transition 1.0, so the engine does not warp the samples a second
  time. The start key's previous transition is stored in the segment record
  and restored by `Clear curve`.
- Rotation segments bake through the same `_curve_value` helper that
  `bake_curve_segment` uses (shortest-arc quaternion slerp for rotation,
  component lerp for position and scale), with the cubic-eased fraction. The
  baked values are always real engine keys, so playback, PNG/GIF/MP4 export
  and GLB export see the same motion.
- The handles are re-editable because the authored values are stored as
  metadata (§7.8). After a bake, the graph draws the authored cubic and the
  actual sampled keys; it does not invent a smooth curve.
- A `Clear curve` action removes the metadata, deletes only the generated
  interior keys, keeps the two endpoint keys and restores the start key's
  recorded transition. It is one undo entry.
- Curve-family presets (Bounce/Elastic/Spring) use the existing
  `bake_curve_segment` path, updated to the same frame-grid rule and
  transition-1.0 rule as the cubic bake. They are marked `Baked preset` and
  show no cubic handles, because they are not cubic. A `Convert to cubic`
  action (96 × 44) replaces the preset with linear cubic handles at the
  current endpoint values; the first handle drag then bakes the new curve.
  Conversion is one undo entry. Until conversion the graph draws the sampled
  keys, so it never claims the family is cubic.

### 7.8 Curve metadata and invalidation

Project format 4 adds, per clip:

```json
{
  "curve_segments": [
    {
      "object": "obj_3",
      "channel": "position",
      "start": 1.0,
      "end": 2.0,
      "family": "cubic",
      "x1": 0.42, "y1": 0.0,
      "x2": 0.58, "y2": 1.0,
      "preset": "ease_in_out",
      "samples": 29,
      "restore_transition": 1.0
    }
  ]
}
```

- `family` is `cubic`, `preset` or `baked`. Preset-family records
  (Bounce/Elastic/Spring) carry `preset` but no handles; `baked` records are
  legacy engine eases that were sampled into keys and also have no handles.
  `samples` is the number of interior keys the last bake wrote; a re-bake
  recomputes it rather than trusting it. `restore_transition` is the start
  key's transition before the first bake and is what `Clear curve` restores.

- Metadata is stored in `AnimationSystem`'s clip record and serialized in
  `to_data()`. `Document` reads/writes it through the active clip.
  `AnimationSystem.curve_segments()` and `set_curve_segments(Array)` operate on
  the active clip; `Document.curve_segments()` and `set_curve_segments()`
  forward to them and mark the project dirty. These are data operations, not
  separate undo entries.
- `apply_key_edits` gains `preserve_curves := false`. User-facing calls leave
  it false and remove any record overlapping the edited range. The internal
  bake passes true so its own key batch does not delete the record it is
  replacing, then writes the new record.
- Two segments on the same channel may not overlap. A new bake replaces an
  overlapping record.
- A record's `start`/`end` span is its stable identity and selection unit; a
  re-bake does not change it, and after reload the record is selected by the
  same span. The generated interior keys are data, not segments.
- Invalidation:
  - editing/moving/deleting an endpoint or any interior key in the range
    removes the record;
  - changing the channel track wholesale (delete track, apply key batch from
    the timeline) removes overlapping records;
  - the internal bake calls `apply_key_edits(..., preserve_curves=true)` so
    its key batch does not invalidate the record it is replacing; the bake
    then writes the new record. The key edit's undo snapshot predates the
    metadata change, so undo restores the old keys and old metadata, and redo
    restores both new ones;
  - switching clips never leaks metadata across clips.
- Re-baking a recorded segment deletes only the interior generated keys in
  `(start, end)` and inserts the new samples. Endpoint keys are matched by
  time with a 0.001 s tolerance; if an endpoint cannot be found, the record
  is dropped and the graph says "Curve data no longer matches these keys."
  A re-bake keeps the existing record's `restore_transition`.
- `FORMAT_VERSION` becomes 4. Loading format ≤ 3 leaves `curve_segments`
  empty. Saving always writes 4. A v3 project loaded and saved by 0.1.5 must
  still open in 0.1.5 (round-trip test).

4. **Undo:** each bake/clear/preset is exactly one undo entry; undo restores
   the previous keys and metadata.
5. **Persistence:** save/load v4 preserves handles and re-edits them after
   reload by re-selecting the record span; a v3 file loads with no metadata;
   saving writes format 4.
6. **Invalidation:** move an endpoint, edit an interior key, and delete a key;
   each removes the overlapping record and keeps the edited key.
7. **Presets:** all six cubic presets set the expected handles; Bounce,
   Elastic and Spring bake through the family path and show `Baked preset`
   with no handles; `Convert to cubic` shows linear handles; dragging one
   switches to Custom. Applying a preset then dragging a handle is one undo
   entry.
8. **Speed:** the plotted average/peak are finite and match a manual sample
   within tolerance; no edit handle exists.
9. **Touch:** handle hit radius 22; key dot hit 22; tabs/preset chips ≥ 44.
10. **Layout:** at 915 × 412 the pane is 324, the header is compacted, Dope
    has a 192 dp plot and Graph shows the preset rail with a 148 dp plot;
    the stage toggle is disabled with the reason. At 800 × 360 the pane is
    272, Dope keeps 140, and Graph uses the `Presets` menu (140 plot). At
    1280 × 800 the stage preview is 161 dp and on by default; toggling it off
    restores the full 732 dp pane.
11. **No overlay:** the timeline pane is a layout sibling below the stage, not
    a child of the stage host.
12. **Clips:** two clips with different curves do not leak metadata when
    switching.

### 8.4 GLB scene export

Core API: `src/core/glb_export.gd` (`RefCounted`), no UI dependencies.

```
func export_scene(doc, path: String, options: Dictionary = {}) -> Dictionary
# {ok, error, path, bytes, nodes, meshes, animations}
```

Requirements:

- Build a **copy** of the document scene; never mutate the live document:
  - clone each visible object root (skip objects whose `visible` is false);
  - omit imported parts whose live node is hidden or whose
    `part_visibility[path]` is false; do not rely on exporting
    `KHR_node_visibility`;
  - remove every node in the `kinema_editor_only` group (camera/light/empty
    markers). W4 changes `Document._add_marker` to add that group, because
    today it does not;
  - omit nodes whose `visible` is false after the copy is built;
  - reuse the live node names and do not rename them: animation track paths
    are `NodePath("<node.name>:<channel>")`, and the document already keeps
    sibling names unique.
- Include the active clip's real `Animation` resource (`doc.animation`) under
  an `AnimationPlayer`, using a real `AnimationLibrary`. Probe result:
  `GLTFDocument` writes `animations` and re-import creates an
  `AnimationPlayer`; the source player name is not preserved. Tests must not
  assert the player name.
- Include cameras and lights as real glTF cameras/lights.
- Skinned meshes: export the skeleton and skin when `GLTFDocument` supports
  the copied hierarchy. The implementation must round-trip the existing rig
  fixture in a test. If the round-trip fails, the sheet states "Rigged meshes
  export in their current pose without skinning" and the test pins that
  limitation; it must not claim a skin that is not in the file.
- Write to `path` with `GLTFDocument.write_to_filesystem`. Default path:
  `user://exports/Kinema_<project>_<timestamp>.glb`; create the exports
  directory when it is missing.
- Desktop: if the native save dialog is available, ask for the destination
  like the still/sequence paths. Android: write to app storage and show the
  resolved absolute path in the result row. No share intent is added in
  0.1.5; the sheet does not show a Share button.
- Result row: file name, byte size, node/mesh/animation counts, and the path.
- Failure leaves no partial file: write to a temporary `.glb`, validate the
  header, then rename; remove the temp on failure.
- Validation in the core:
  - file starts with `glTF`, version 2, length matches;
  - re-import with `GLTFDocument.append_from_file` succeeds;
  - generated scene node count > 0;
  - if animation was requested and at least one track was retained, the
    re-imported scene has an `AnimationPlayer` with at least one animation.
- `options`: `{"animations": true, "selection_only": false}`. Selection-only
  is offered only when exactly one object is selected; it exports that object
  subtree. The sheet states the scope.
- Animation scope: with `selection_only`, only tracks whose paths resolve
  inside the exported subtree are retained. If none resolve, the export still
  succeeds with `animations: 0` and the result row says "No animation on this
  selection"; validation then does not require an `AnimationPlayer`. Without
  `selection_only`, tracks that target excluded objects are dropped and the
  reported animation count reflects what was retained.
- The exporter does not export the editor environment, grid, overlays, video
  reference, rig handles or UI.

## 12. Risks and mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Shell rewrite breaks many old tests | W1 stalls | W1 is shell plus the rig-action migration only; rewrite layout/smoke in the same change; migrate every assertion; run the full gate before W2 branches |
| Workspace naming collides with layout naming | Confusing APIs and bugs | R14 rename in W1; update Main and tests in one commit |
| Context row overflows at 360/800 | Unreachable actions | Explicit per-workspace priorities + overflow menu; layout test at 360 × 640 and 800 × 360 |
| Rig gizmo math feels wrong or misses | Core fix fails on touch | Reuse the object gizmo's projected-axis approach; 22 px hit tests; axis tests in `rig.gd`; keep head/tail handles |
| Edit-mode drag changes the wrong thing | Data corruption | Precedence table; rest edits preview locally and commit once; undo diff test |
| Redraw optimization leaves stale bones | Visual bug | Mark dirty on camera transform + every rig signal + playback; test idle and camera-move draws |
| Cubic bake bloats keys or changes playback | Animation integrity | frame-grid samples capped at 48; endpoint preservation; playback sampling tests; metadata invalidation; fallback ruling R7 |
| Project format 4 breaks older files | Data loss | Load 1–3 unchanged; round-trip test; metadata optional; no schema changes to existing fields |

## 15. Builder-check resolutions

Independent builder review ran against the codebase on 2026-11-04. Seven
questions were raised; all were resolved by the author, and none changes what
the user is approving.

1. **W1 gate depended on W3's Animate pane.** W1 test 8 now asserts only
   that the Animate pane is a real layout sibling holding the mounted
   `Timeline` and not covering the stage. The stage-preview split, compacted
   header and plot budget moved to W3 test 10; `Prefs.editor.animate_stage`
   and `graph_tab` are explicitly W3-owned. W1's Animate context row is
   `fit` + `more`; W3 adds Dope/Graph and `stage_toggle`.
2. **Segment identity after a bake was undefined.** The segment model now
   distinguishes a recorded segment (the record's `start`/`end` span, one
   selectable unit) from a plain key interval. Selection identity is
   `object + channel + start + end + kind`; prev/next and graph taps skip
   interior baked keys, and a reload re-selects by span. §7.2, §7.8 and the
   W3 tests state this.
3. **Camera switching exited look-through.** `EditorView` gains
   `switch_look_through_camera(id)`; it preserves `_look_saved` and chrome
   and does not emit `look_through_exited`. `enter_look_through` delegates to
   it when already active, and `Editor._enter_camera_view` uses it for the
   active case. The camera test asserts no exit signal on switch.
4. **W4 `materials.gd` scope was ambiguous.** W4 migrates the inspector and
   smoke assertions to the Shading workspace, as now stated in §8.5.9; the
   material model, assignment, UV and texture tests stay unchanged, and no
   modal shim is kept.
5. **Preset rail vs the 192 dp plot.** The 192 dp figure is Dope mode. At
   915 × 412 Graph shows the 44 dp rail and keeps a 148 dp plot (still above
   the 120 dp floor). At 800 × 360 the rail is hidden and the `Presets` menu
   is used. §7.1 and W3 test 10 now agree.
6. **Stage preview height mismatch.** `clamp(body * 0.22, 96, 200)` gives
   161 dp at 1280 × 800 with the instrumentation strip off (the default).
   The stale 157 dp literals are gone.
7. **`editor.layout` looked like a persisted-key rename.** The persisted key
   remains `display.layout`; W1 renames only the in-memory API to
   `layout_mode`. The preferences table and its note now say so, and no
   migration is required.
