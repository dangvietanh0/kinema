# Kinema Studio 0.1.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Kinema Studio 0.1.5 with a five-workspace shell, one-gesture rig editing, a segment-based graph editor that bakes real cubic keys, a real in-camera path, embedded shading/render workspaces, real GLB export, and a verified 0.1.5 Android debug APK.

**Architecture:** Four workstreams branch from the approved spec commit. W1 replaces the crowded shell with `WorkspaceBar`, `ContextBar`, `TransportBar`, `StageHost`, `WorkspacePanel`, a workspace menu and a project menu; it also adds the camera view, renames the layout API, migrates every old-shell test and owns the version bump. W2, W3 and W4 branch from W1 and run in parallel: W2 fixes rig interaction and adds the gizmo, W3 adds format-4 curve metadata, cubic baking and the `SegmentGraph`, W4 embeds the existing material/export surfaces and adds `GlbExport`. W2/W3/W4 merge into `wave4/integration` in order, with the full gate after every merge.

**Tech Stack:** Godot 4.7.2, GDScript, `Animation`/`Skeleton3D`, `GLTFDocument`/`GLTFState`, the existing `Document`/`AnimationSystem`/`MaterialSystem`/`RigSystem`, and the repo's headless suite runner.

**Spec:** `docs/superpowers/specs/2026-11-04-kinema-0.1.5-design.md` (binding; read it before every task).

## Global Constraints

- **Platform:** Android 15–17 target, touch first, landscape priority. Desktop remains a first-class window mode but is not the primary target.
- **Touch targets:** 44 dp minimum in Compact and Studio; 44 dp rows in menus and panels. Primary actions are 96 × 44 dp. Desktop may use 28–32 dp mouse controls; the 44 dp floor applies to touch layouts only.
- **Landscape budgets:** the shell must fit 800 × 360, 915 × 412, 600 × 960, 360 × 640, and desktop 1024 × 768 through 2560 × 1600 without horizontal overflow.
- **Chrome:** pure black window and stage; achromatic graphite elevation; red only for destructive/error. No new colour accents.
- **Type:** IBM Plex Sans and IBM Plex Mono, existing tokens. 11 sp is the product floor; 10 sp only on ruler ticks and non-essential mono badges.
- **Corners:** square panels. Existing 2 px control and 4 px floating-surface radii stay; no new large radii.
- **No fake features:** every enabled control performs the action its label claims. A capability the platform cannot provide is disabled with the real reason.
- **No new shaders:** no `.gdshader` file is added or modified in 0.1.5.
- **Data compatibility:** format 3 and older project files load unchanged. Format 4 adds optional per-clip `curve_segments`.
- **Build:** only GitHub Actions `assembleStandardDebug`, arm64-v8a, CI debug keystore, package `studio.kinema.app`.
- **Version:** `0.1.5`, Android versionCode `2`, artifact/APK `Kinema-Studio-0.1.5-arm64-debug`.
- **One glyph, one meaning:** the §5.10 icon table is binding; `camera` never means render, `restart` never means reset, `play` never means preview, `focus` never means fullscreen.
- **Model rule for subagents:** every subagent stays on `opencode/deepseek-v4.1-flash-free`. Never switch provider or model.
- **No device-validation claim:** the APK is verified by inspection; §13 device checks remain unverified.

### Binding technical resolution: `layout_mode` is a getter

Godot's `Control` already owns a native `layout_mode` property; a script member with that name fails to parse (`Member "layout_mode" redefined`). W1 therefore implements the spec's rename as:

- private `var _layout_preset := "studio"`;
- public `func layout_mode() -> String` (the old `workspace_mode()` name moves here);
- `func set_layout_mode(mode: String) -> void`;
- `signal layout_mode_changed(mode: String)`.

This is the only deviation from the spec text; it preserves the required names and avoids shadowing an engine property. All tests use `editor.layout_mode()`.

## Review Focus

These are the uncovered input/failure classes most likely to bite a real user. Each one is pinned by a named test in the task that owns the code.

1. **Switching workspace while a panel, modal or rig drag is active.** A stale panel must not float over the new workspace, a modal must close first, and a live rig drag must commit or cancel exactly once. Tests: `shell.gd::_test_workspace_switch_with_open_surfaces` (Task 7), `rig.gd::_test_drag_cancel_on_disable` (Task 14).
2. **The active camera disappears while look-through is running.** Deleting the camera, undoing its creation or loading another project must exit look-through with the exact toast, never leave a camera view pointing at nothing. Test: `shell.gd::_test_camera_view` deletion guard (Task 6).
3. **A cubic bake at the edges of the frame grid.** A 2-frame segment, a 3-frame segment, a 10-second segment, a quaternion channel and a re-bake must never duplicate keys, land on an endpoint, or exceed 48 interior keys. Test: `graph.gd::_test_cubic_bake_edges` (Task 21).
4. **GLB export of a document containing hidden imported parts and editor markers.** The file must contain neither markers nor hidden parts, must contain real cameras/lights, and must leave the live document unchanged. Test: `export.gd::_test_static_scene_export` (Task 22).
5. **Opening an old format-3 project with engine eases, material assignments and an imported rig.** It must load, edit and save as format 4 without losing data. Test: `graph.gd::_test_v3_round_trip` (Task 21), `materials.gd` (existing, migrated in Task 25).

static func cubic_ease(t: float, x1: float, y1: float, x2: float, y2: float) -> float:
    var target := clampf(t, 0.0, 1.0)
    if target <= 0.0:
        return 0.0
    if target >= 1.0:
        return 1.0
    x1 = clampf(x1, 0.0, 1.0)
    x2 = clampf(x2, 0.0, 1.0)
    y1 = clampf(y1, -2.0, 3.0)
    y2 = clampf(y2, -2.0, 3.0)
    var s := target
    for _i in range(8):
        var x := _cubic_bezier(s, x1, x2)
        var dx := _cubic_bezier_derivative(s, x1, x2)
        if absf(dx) < 0.000001:
            break
        var next := s - (x - target) / dx
        if next < 0.0 or next > 1.0:
            break
        s = next
        if absf(x - target) < 0.0000001:
            break
    var lo := 0.0
    var hi := 1.0
    for _i in range(32):
        var x := _cubic_bezier(s, x1, x2)
        if absf(x - target) < 0.0000001:
            break
        if x < target:
            lo = s
        else:
            hi = s
        s = (lo + hi) * 0.5
    return _cubic_bezier(s, y1, y2)

  * compute `start_frame/end_frame/span_frames`; if `< 3`, return the exact
    short reason; `n = clampi(span_frames - 1, 1, 48)`;
  * sample only the interior for `i in range(1, n + 1)`: frame
    `start_frame + round(i*span_frames/(n+1))`, collapse duplicates, times
    `frame/fps`, fractions `(time-start)/(end-start)`. The loop never emits
    `i == 0` or `i == n + 1`, so an endpoint key is never re-inserted or
    moved;
  * build edits: delete every existing key strictly inside `(start,end)`
    (by index), set the start key transition to 1.0, insert each sample with
    `value = _curve_value(channel, v0, v1, eased_fraction)`, transition 1.0;
  * call `_apply_key_edits_raw(id, channel, edits, "Bake curve", true,
    channel_records)` where `channel_records` is `segments_for(id, channel)`
    with every record overlapping `(start,end)` removed and `new_record`
    appended. The new record carries the `start/end` passed to the bake,
    `samples` count, `family`, `preset`, handles and `restore_transition`;
  * return `{ok, inserted, reason, message}`.
  * `_bake_curve_range` must not mutate before validation. It calls a
    read-only `_bake_curve_plan(id, channel, start, end) -> Dictionary` (the
    same endpoint/span lookup used by the raw body) first; when the plan is
    invalid it returns the reason without `begin_edit`. When valid it calls
    `begin_edit("Bake curve")`, runs the raw body, `cancel_edit()`s if the raw
    body still refuses, else `end_edit()`s. `Document.end_edit()` records no
    undo entry when nothing changed, so a refused bake writes neither undo
    nor metadata.
- Every public bake resolves `restore_transition` before it rewrites keys:
  reuse the record it replaces when one spans the range, otherwise capture the
  start key's current transition. Clear curve later restores that exact value;
  a re-bake (handle drag, endpoint move) must carry it forward, never reset it
  to 1.0.
- `bake_cubic_segment(id, channel, start, end, x1, y1, x2, y2, preset := "custom")`
  uses fractions from `SpeedCurve.cubic_ease(fraction, x1, y1, x2, y2)`, keeps
  the caller's preset id (the rail passes `ease_in_out` etc.; a handle drag
  passes `"custom"`), preserves `restore_transition` as above, and writes
  `family: "cubic"`.
- `bake_curve_family_segment` uses `SpeedCurve.evaluate(family_id, fraction)`
  with the same frame grid and transition rules; `family: "preset"`,
  `preset: family_id`, no handles. Keep `bake_curve_segment` as a compatibility
  wrapper that resolves the selected→next key times and calls this.
- `bake_engine_ease` samples the live track with
  `sample_channel(id, channel, time)` at the same frame-grid times (so the
  real engine ease is captured, including Godot's cubic interpolation), sets
  the same transition 1.0 rule, and writes `family:"baked"`,
  `preset:"engine"`, `restore_transition` from the start key. It uses the
  key's following key as the end.
- `clear_curve_segment` finds the record and owns one
  `begin_edit("Clear curve")` / `end_edit()` pair. If an endpoint is missing,
  drop only the record with `set_curve_segments(...)`, keep every key, and
  return the "no longer matches" reason. Otherwise call
  `_apply_key_edits_raw(id, channel, edits, "Clear curve", true,
  segments_without_record)` once to delete all keys strictly inside
  `(start,end)` and set the start key transition to `restore_transition`,
  then `end_edit()`. Never call `apply_key_edits` inside this transaction: its
  own `end_edit()` would commit the outer snapshot early.
- `convert_segment_to_cubic` removes the record and writes a new one with
  `family:"cubic"`, handles `(1/3,1/3,2/3,2/3)`, `preset:"custom"`, the same
  span and `restore_transition`; no keys change. It is one
  `begin_edit("Convert to cubic")` / `end_edit()`.
- `curve_segments()` must be read/written on the active clip only; switching
  clips never leaks records.

## Step scan

Every task has: exact files, consumed/produced interfaces, a failing test,
an implementation step, a run command, and a commit. Intermediate shell/panel
tasks may leave an old suite failing for a named later migration; every
workstream gate (W1 Task 10, W2 Task 14, W3 Task 21, W4 Task 26, Final Task
27) is all-green, and no suite is disabled. The new suites (`shell`, `graph`,
`export`) are created before the code they exercise. Existing suites are
migrated in the workstream that breaks them, never deleted.

## Type consistency

- Godot `Control` owns `layout_mode`; the editor uses private
  `_layout_preset`, `layout_mode()`, `set_layout_mode()`,
  `layout_mode_changed`.
- `SegmentGraph` uses `PackedStringArray` for preset ids and `PackedVector2Array`
  for points; `Range` typo avoided.
- `Document.apply_key_edits` gains only trailing optional parameters, so every
  existing caller compiles unchanged.
- `curve_segments` is always an `Array` of `Dictionary`; a missing field means
  empty.
- `GlbExport.export_scene` returns `Dictionary`; never a `Node`.
- All new touch rows are 44 dp; all primary actions 96 × 44; the graph hit
  radius is 22 px.

## Review focus

1. **Shell does not regress the stage.** Scene has no permanent side column;
   Animate is a sibling below the stage; Rig never mounts the timeline.
2. **Rig input precedence is exact.** Handles → gizmo → IK → bone body → empty.
   One gesture selects and drags; tap is not an undo entry.
3. **Curve identity is segment-based.** A record counts once; interior baked
   keys never become selections; prev/next skips them; invalidation is
   atomic with the key edit.
4. **Bake integrity.** Frame grid, 1–48 interior keys, endpoints preserved,
   transition 1.0, real engine keys, playback/export parity.
5. **GLB never lies.** Markers and hidden nodes are absent, live document is
   untouched, selection and animation scopes are reported, failures leave no
   partial file, skin support is either proven or pinned as a limitation.
6. **No fake UI.** Every action calls a real document/export API; disabled
   controls state their reason.

## Open implementation choices (already pinned)

- `Timeline` keeps the existing dope-sheet body and adds the new graph body;
  the old `_draw_graph` speed path is removed in W3 Task 17.
- The preset rail lives inside `SegmentGraph` (it owns the 44 dp row and plot);
  the graph header is owned by `Timeline`. This matches the fixed-row math in
  §7.1.
- The graph header is a second row at ≥ 400 dp pane height; it merges into the
  pane header below 400 dp at width ≥ 600 dp.
- Value endpoint drags use `Document.move_key` so the key edit and the re-bake
  are one undo entry. Interior drags invalidate the record and keep the key.
- Preset application and a later handle drag are separate gestures and
  separate undo entries; no two user gestures are merged.
- `GlbExport` validation re-imports the temp file before renaming; the final
  destination is only written after validation succeeds.
- Device-only checks remain unverified and are reported as such.
